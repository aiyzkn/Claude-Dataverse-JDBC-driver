## 1. 前提と互換性の確認結果

ゲートウェイは .NET 8（TFM `net8.0`・RID ハードコードなし）で、Linux コンテナへ**コード変更なしで配置可能**。
プラットフォーム依存箇所は次のとおり確認済み:

| 箇所 | Linux での挙動 |
|---|---|
| スリープ抑止（`SetThreadExecutionState`） | `OperatingSystem.IsWindows()` でガード済み → **no-op**（コンテナに不要） |
| Windows サービス（`UseWindowsService`） | 非 Windows では **no-op** |
| 多重起動ガード（名前付き Mutex） | コンテナは 1 プロセス/1 ネットワーク名前空間のため実質不要。クラッシュしない |
| 永続データパス（`LocalApplicationData`） | 非 root ユーザーでは `$HOME` からの解決が不確実で**空に落ち**、CWD 相対で `/app`（実行ファイル）と衝突しクラッシュした。**`XDG_DATA_HOME=/data`** を明示（.NET が最優先で参照）して `LocalApplicationData=/data` に固定・ボリューム化（Dockerfile 済） |
| TLS 証明書 | **`Gateway:Tls:CertPath`（PFX）を使用**。`Thumbprint`（Windows 証明書ストア）は Linux 非対応 |
| 認証 | **ClientSecret / Certificate のみ**（対話型/デバイスコードはブラウザ不可のため使用不可） |
| 読み取り経路 | TDS/FetchXML とも動作（TDS は AAD トークンでの接続。既定 auto。macOS で TDS 動作確認済＝Unix 系で到達可） |

## 2. ビルド

ビルドコンテキストは**リポジトリルート**。

```bash
docker build -f dist/Dockerfile -t dataverse-gw:1.0.0 .
```

マルチステージ: `sdk:8.0` で restore→publish（フレームワーク依存）、`aspnet:8.0` へ成果物のみコピー。
csproj を先にコピーして restore をレイヤーキャッシュ。非 root（`$APP_UID`）で実行。

## 3. 実行

認証情報は**環境変数**で注入（コミット/共有厳禁）。永続データは `/data` ボリュームへ。

```bash
docker run --rm -p 32010:32010 \
  -e DATAVERSE_URL=https://<org>.crm7.dynamics.com/ \
  -e DATAVERSE_AUTH=ClientSecret \
  -e DATAVERSE_TENANT_ID=<tenant> \
  -e DATAVERSE_CLIENT_ID=<client> \
  -e DATAVERSE_CLIENT_SECRET=<secret> \
  -v dvgw-data:/data \
  dataverse-gw:1.0.0
```

- 既定で `Gateway__Bind=any`（0.0.0.0。localhost バインドだとコンテナ外へ届かない）。
- クライアントは `grpc://<host>:32010`（TLS 時は `grpc+tls://`）で接続。

### TLS（ネットワーク公開の必須要件）
ネットワーク公開では資格情報・データが流れるため **TLS 必須**。PFX をマウントして指定:

```bash
docker run --rm -p 32010:32010 \
  -e DATAVERSE_URL=... -e DATAVERSE_AUTH=ClientSecret \
  -e DATAVERSE_TENANT_ID=... -e DATAVERSE_CLIENT_ID=... -e DATAVERSE_CLIENT_SECRET=... \
  -e Gateway__Tls__CertPath=/certs/gateway.pfx \
  -e Gateway__Tls__CertPassword=<pfx-password> \
  -v dvgw-data:/data -v /host/certs:/certs:ro \
  dataverse-gw:1.0.0
```

### 複数SPスケールアウト（4.2.4）・接続先クライアント供給（B2）
いずれもコンテナで利用可（環境変数/ヘッダは配置形態に依存しない）。
- スケールアウト: `Gateway__ScaleOut__Principals__0__ClientId` 等を注入。
- B2: 起動時 `DATAVERSE_URL` 未設定でも起動でき、クライアントが gRPC ヘッダで接続先供給（setup-guide §7.6）。

## 4. 主な環境変数（コンテナでよく使うもの）

| 変数 | 用途 |
|---|---|
| `DATAVERSE_URL` / `DATAVERSE_AUTH` / `DATAVERSE_TENANT_ID` / `DATAVERSE_CLIENT_ID` / `DATAVERSE_CLIENT_SECRET` | 起動時接続（既定コンテキスト） |
| `Gateway__Bind`（既定 any）/ `Gateway__Port`（既定 32010） | バインド/ポート |
| `Gateway__Tls__CertPath` / `Gateway__Tls__CertPassword` | TLS（PFX） |
| `Gateway__CheckpointDb` | チェックポイント DB パス（既定 `$HOME/.local/share/...`） |
| `Gateway__ScaleOut__Principals__N__*` | 複数SPスケールアウト |
| `HOME`（Dockerfile で `/data`） | 永続データの基点（ボリューム） |

## 5. 制約・留意点

- **対話型/デバイスコード認証は不可**（ヘッドレス）。ClientSecret / Certificate を使う。
- **TLS は CertPath（PFX）**。Windows 証明書ストア（Thumbprint）は Linux 非対応。
- 永続データ（チェックポイント/監査/失敗レポート/トークン）は `/data` ボリュームに置く（コンテナ再作成で消えないように）。
  監査/ドライラン/トークンのパスは現状 `LocalApplicationData` 固定のため、`HOME=/data` 経由で集約している。
- ヘルスチェックは未同梱（gRPC のため）。必要なら TCP レベル（32010 の疎通）で構成する。
